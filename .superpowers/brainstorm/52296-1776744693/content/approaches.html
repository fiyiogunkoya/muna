How should we architect admin-managed content?

Three approaches for letting non-technical admins upload photos, manage galleries, and change fonts — all through Sanity Studio

A

Sanity-Native (Recommended)

Everything lives in Sanity schemas. Add a gallery document type with image arrays, a siteTheme singleton for font selection, and extend existing page/post schemas. Admins do everything in the Sanity Studio they already have.

Pros

  • Single admin interface — no extra tools to learn
  • Built on what you already have (schemas, studio, visual editing)
  • Real-time preview of font changes via Presentation Tool
  • Image CDN, hotspot cropping, and Unsplash already wired up
  • Cheapest to build and maintain

Cons

  • Bulk photo uploads can be tedious (one at a time in Sanity)
  • Gallery layout is code-defined, not drag-and-drop
B

Sanity + External Image Service

Use Sanity for content and fonts, but integrate Cloudinary or a similar service for photo management. Admins upload photos in Cloudinary's media library, then reference them in Sanity.

Pros

  • Better bulk upload and image management UI
  • Advanced image transformations (auto-crop, filters, watermarks)

Cons

  • Two tools for admins to learn (Sanity + Cloudinary)
  • Extra monthly cost for Cloudinary
  • More integration complexity
  • Sanity already has a solid image CDN
C

Custom Admin Dashboard

Build a separate, simplified admin UI on top of Sanity's API. Admins get a custom drag-and-drop interface instead of using the Sanity Studio directly.

Pros

  • Fully custom UX tailored to your admins
  • Can hide all Sanity complexity

Cons

  • Significant extra development time
  • Two codebases to maintain
  • Reinvents what Sanity Studio already does well
  • Overkill for 1-2 admins
